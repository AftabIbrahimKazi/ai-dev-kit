# UI Standards — System States

Read when: adding loading, empty, error or offline handling, a long job, or a 404/403/500/503 page.

- **UI-STA-01** Render the shell (header, sidebar, page header, filter bar, table column headers) without waiting for any data request. Only data regions (table rows, cards, widgets, detail sections) wait, each with its own skeleton. A server-rendered page does not hold its response for a slow query; the region loads lazily or streams in. Every data region defines loading, empty and error states, and an offline state when the product is offline-capable; show each in the PR (screenshots or snapshots).
- **UI-STA-02** Wait under 300 ms: show nothing. Once an indicator shows it stays at least 500 ms to avoid flicker. 300 ms to 2 s: a skeleton or inline spinner. Over 2 s: add progress text. Over 10 s: run it as a background job with a status and a notification.
- **UI-STA-10** Pick the indicator by situation: first load of a region, the skeleton matching the final layout; refresh of shown data (filter, sort, page), content dimmed to 60% with a 2 px progress bar on top of the region; button action, a spinner inside the button with the "-ing" label and `aria-busy`; small inline load (picker options), a 16 px spinner and "Loading…"; client-side route change, a 2 px progress bar under the header; over 10 s, a background job.
- **UI-STA-03** A skeleton keeps the final layout size, so Cumulative Layout Shift stays at or under 0.1. Use neutral blocks in the hover-tint colour, mark the region `aria-busy="true"` with visually hidden "Loading <entity>", and use at most a subtle pulse that stops under `prefers-reduced-motion`.
- **UI-STA-09** A data request times out after 15 s (configurable per endpoint) and shows the region's error state with Retry. Cancel superseded requests (`AbortController`). Work expected over 10 s is a background job, not a long request. No indefinite spinner.
- **UI-STA-04** An empty state says why it is empty and offers at most one primary and one secondary action. Types: first use (icon, "No <entity> yet", one line on its purpose, primary "Add <entity>", optional secondary such as "Import from CSV"; the filter bar and table are hidden); no match (`filters.md`); all caught up (success icon, "You're all caught up", one line, optional "View all …"); no access (lock icon, "You don't have access to <module>", the role to request, "Go to Dashboard", page actions hidden). Anatomy: 56 px icon in a soft circle, `<h2>` title (18 px, 600), at most two lines of text, centred in the region's card. No illustrations until the brand has an illustration set.
- **UI-STA-11** When a role lacks a whole module show the no-access state or a 403 page. When a user requests a specific record they may not access, respond and show 404 "Page not found", not 403, so existence is not confirmed.
- **UI-STA-05** An error is per region: an inline danger alert inside the region (`role="alert"`) with a short title ("Couldn't load <data>"), the cause in plain words, and Retry. Keep the data already shown and the rest of the page working.
- **UI-STA-12** Independent regions (dashboard widgets, detail-page tabs, side panels) load and fail independently; one failure never replaces the whole page. A bulk operation reports partial results ("10 updated, 2 failed") with the reason per failed record.
- **UI-STA-13** Exports, imports, bulk updates and reports over 10 s run as background jobs: a persistent progress toast ("Exporting 2,480 laptops… 45%" with "Hide") the user can hide while the job continues, and may navigate away. On completion a success toast (if online) and a bell notification linking to the result. On failure a notification with the reason and Retry. Download links need authentication and expire (24 h default).
- **UI-STA-06** Offline (browser `offline` event or repeated network failures): show a banner, say which actions are paused, keep everything typed, never drop a write silently. PWA and native apps queue safe changes marked "Pending sync"; actions that need the server are disabled with "Needs a connection". On reconnect toast "Back online · N changes synced"; sync conflicts follow the edit-conflict rule in `forms.md`. Native offline queues are encrypted on device.
- **UI-STA-07** 404, 403, 500 and 503 pages render inside the app shell when signed in (guest layout otherwise), use the page header `<h1>` as title, and show a large muted status code, one or two plain sentences, a primary next step and an optional secondary. Titles: 404 "Page not found"; 403 "You don't have access to this page"; 500 "We couldn't load this page" (with "Try again" and a support code); 503 "Scheduled maintenance" (with a back-by time). HTTP status codes match the page; 503 sends `Retry-After`.
- **UI-STA-14** Every 5xx page, failed save and failed job shows a short support code (`ERR-7F3A`) mapped to the server correlation ID, in monospace with a "Copy code" button. Never a stack trace, SQL, file path or framework name in the UI.
- **UI-STA-08** Loading regions set `aria-busy`. Announce async status with `role="status"` and errors with `role="alert"`, once. Background loads never move focus. Completion of user-started work is announced politely.
- **UI-STA-15** Flutter and React Native apps implement the same states with the same texts; lists support pull-to-refresh with the platform indicator.
