# UI Standards — Review Checklist and Self-check

Read when: finishing any UI change, writing a UI pull-request description, or reviewing one.

- **UI-CHK-01** End every UI change with a self-check line per partial used, listing each rule ID as ✅, n/a with a reason, or ❌ with a reason: `UI self-check (header.md): UI-HDR-01 ✅ · UI-HDR-06 n/a (single tenant) · …`, then `STANDARDS GAP: none` or the gaps. A rule left unmet is a ❌ with the reason, never silently skipped.
- **UI-CHK-02** Copy the "Every UI change" block into the pull-request description, then add the blocks for the page types touched. Items marked (CI) are checked by tools; the reviewer confirms the job passed. Other items need a human look.
- **UI-CHK-03** Scope: new screens fully; modified screens for the regions touched, plus every accessibility and security item for the whole screen. Untouched screens are not retrofitted.
- **UI-CHK-04** A rule that cannot be met is listed in the pull request with rule ID, reason, impact, expiry date and approver (in code: `DEVIATION: <rule id> <reason>`). Accessibility and security rules cannot be waived.

## Every UI change

- **Tokens and theming:** no literal colours, sizes or fonts and no palette classes (CI); generated token files not edited by hand and the token check passes (CI); light and dark both reviewed and approved (CI snapshots); primary colour only where allowed (buttons, links, focus, active states).
- **Layout and navigation:** page header with breadcrumb at depth 2 or more, one `<h1>` (CI), at most 1 primary and 2 secondary actions; controls 36 px (28 in tables, 32 in toolbars, 44 on touch).
- **States and feedback:** loading (shell first, structural skeleton), empty, error and offline states done; feedback component chosen from the matrix, no error toasts, no "Something went wrong"; irreversible actions confirmed, reversible actions offer Undo.
- **Accessibility, whole screen:** axe finds no serious or critical violation in light and dark (CI); keyboard-only walk-through reaches every action with visible focus and no trap; focus never hidden under a sticky header or footer; targets at least 24 px (44 px on touch) and dragging has a button alternative; meaning never by colour alone; 200% zoom and text size without loss or overlap.
- **Security, whole screen:** unpermitted actions hidden and every endpoint authorised on the server; output escaped, no unescaped HTML output or `dangerouslySetInnerHTML` without sanitising (CI); CSRF on state-changing requests (CI); no sensitive data in URLs, toasts, logs or exports.
- **Content:** verb-first labels in sentence case, one date and amount format per product; no placeholder or invented data in production builds.
- **AI-generated code:** the self-check lists the applied rule IDs and any `STANDARDS GAP`. Never paste production data, customer or employee personal data, tenant data, secrets (`.env`, keys, tokens, passwords) or Restricted fields into prompts, chats or generated code; use seeders, factories and fixtures with sample records (`LT-0042`). Generated code never logs, shows, exports or puts in URLs a Confidential or Restricted field.

## If the change touches

- **A list page:** filters in the URL, chips, "Showing N of M", a no-results state naming the filter; the shared table component, at most 7 default columns, sticky header, identifier link, at most 2 icon actions plus ⋯; page size 25 with server-side pagination and sorting (CI); export with header block, page numbers, classification and the formula-injection guard.
- **A form:** 12-column grid, label above, one message line; any option list is a searchable select, radios only for Yes/No; errors under fields, focus on the first invalid field, Save never disabled for validation; server validation mirrors client rules and 422 maps to fields (CI); unsaved-changes guard on every exit.
- **Uploads or images:** the shared upload component, chunked transfer, every file shows a state; images lazy, right-sized, fixed ratio, broken ones fall back to the default image (CI).
- **A dashboard or chart:** chart type from the selection table, calm palette, dashed second series; tooltip on focus, View as table, widget states; server aggregation and sampling for big charts.
- **Authentication:** generic credential error, lockout and rate limits (CI); 2FA enforced on the server, no SMS.
- **A public or landing page:** Lighthouse 90 or more in all four categories and LCP under 2.5 s (CI); spam check verified on the server, no trackers before consent.
- **A mobile app or PWA:** golden tests in light, dark and at 200% text (CI); platform back behaviour, bottom navigation, gestures have ⋯ alternatives; valid manifest, update toast, offline page (CI).

## Automation map

- **UI-CHK-05** What tools check: tokens and literal colours (build check, contrast script, Stylelint, ESLint, Flutter and React Native lint); dark mode (screenshots in light and dark colour schemes); components (ESLint restricted syntax and imports, template lint for raw `<select>`, `type="date"`, raw `<img>`, `select2`, unescaped output, hex colours, inline style); accessibility (axe-core, jsx-a11y, Flutter accessibility guideline API, react-native-a11y); layout and navigation (one `h1`, breadcrumb at depth 2 or more, `aria-current`); tables and filters (URL state, page size 25, sticky header, server pagination, permissions); forms (focus on first error, no disabled Save, discard guard, 422 mapping); system states (mocked slow, empty, failing and offline responses); uploads (contract tests such as Schemathesis, lazy loading, fixed ratio, broken fallback, magic bytes, EXIF); exports (golden-file tests that open XLSX and PDF and assert header, footer and formula guard); dashboards (contrast, tooltip on focus, table toggle, performance at 365 and 3,650 points); performance (Lighthouse CI budgets, startup and frame tests); auth and security (enumeration, lockout, CSRF API tests; OWASP ZAP baseline on staging); mobile and PWA (golden tests, Detox or Maestro flows, Lighthouse PWA checks).
- **UI-CHK-06** What stays manual: choosing the right chart, control or feedback component; wording, labels and error messages; keyboard and screen-reader walk-through; focus not obscured by sticky elements in real layouts; approval of visual diffs in light and dark; waivers.
- **UI-CHK-07** Config the tools use: Stylelint `color-no-hex`, `color-named: never`, a disallowed list of `rgb`, `rgba`, `hsl`, `hsla`, `hwb`, `lab`, `lch`, `oklab`, `oklch`, and no `px`, `rem` or `em` on padding, margin, gap, border-radius and font-size (ignore the generated token files); ESLint `no-restricted-imports` for jQuery, select2 and chart.js and for third-party UI kits, `no-restricted-syntax` for raw `img`, `select`, `type="date"`, `type="number"` and colour literals, plus `jsx-a11y`; Playwright with axe for every key route in both colour schemes asserting one `h1`; Lighthouse CI asserting performance, accessibility and best practices at 0.9 or more, LCP 2500 ms or less, CLS 0.1 or less, TBT 200 ms or less. Pipeline stages: validate, test, performance, mobile, security.
