# Changelog

## 2026-11-11

### Added
- `skill-hint` mod 0.2.0: on a prompt that matches perf-audit's triggers (slow, perf, bundle, lighthouse, page weight, load time, vitals) it runs `perf-audit/weigh.js` once per session, when that skill is installed and active, and attaches the table to the prompt, so the payload facts arrive with no skill load. Measured first (Haiku, one Astro build of 148 files, 2 runs per arm): model-led $0.0197 and $0.0186 with 16.1k and 14.0k output tokens over 11 and 8 turns; script-led $0.0056 and $0.0057 with 2.2k and 2.4k output tokens over 2 turns. The table is capped at 60 lines; any run problem means no table. Checked by unit test only, not yet in a live session.
- `skill-hint` now routes plain-language prompts to eight more skills (code-audit, security-audit, memory-gardener, optimize-assets, project-context, diagram, pre-commit, untrack) through phrase triggers chosen to avoid common words ("audit log", "recipe" do not match). Five of them also run a read-only script once per session: `code-audit/audit.js --top 15`, `security-audit/recon.js --top 20`, `memory-gardener/stale.js`, `optimize-assets/convert.js scan`, `project-context/scan.js status`. Nothing that writes, converts or installs is run, and `pre-commit` gets the hint only (its check exits 1 on a BLOCK, which the runner treats as a failure). Unit tests (9 pass) and standalone runs of all five scripts. Measured live for the audit prompt only ("audit the project against our standards, worst rule and its count"; headless Haiku, 3 runs per arm, real `audit.js`, 6 small files): without the hint $0.0120 mean, 6.7 turns, 1,966 output tokens; with it $0.0040, 2.3 turns, 916 output tokens (-67% cost); both arms gave the same correct answer (js-03, 12 violations). The other four scripts are covered by the same code path but not measured live. `recon.js` can exceed the 30 s hook limit on a large repo (then no table, hint line only).
- `/next` is now script-first: `skill-scope/auto.js apply --require-task` writes the `## Next task` line and the `## Skills` block into `handover.md` itself (replaces only those two sections, creates the file if missing, drops an empty Skills block, leaves a `handover/` folder to the model and says so). The command file shrank from 20 lines to 14 and keeps only the relay and the `tsk-start` branch. 3 new tests; token cost not yet measured.
- `/pickup` is script-first: `skill-scope/auto.js pickup` prints the queued task with what its mode means (queued, not started, or begun), the handover verbatim, then the archived-skills report, and `NO_HANDOVER_FILE` when there is none (it also works in a project with no install manifest, as the old command did). The command file is now a short relay. 2 new tests; token cost not yet measured.
- `/audit`, `/perf` and `/recon` print their own summary: `code-audit/audit.js --summary` (worst 5 rules, worst 5 files, the biggest fix by count), `perf-audit/weigh.js --summary` (at most 7 rows ranked by bytes, each with a fix and S/M/L effort from a lookup) and `security-audit/recon.js --summary` (a grouped map under 20 lines: route files with no auth marker, sink classes, obvious items, a "check first" order; no finding named). The three command files are now short relays. 6 new tests; token cost per command not yet measured.
- `/commit-check` ends with a one-line verdict (STOP, REVIEW, SAFE or nothing staged) from the script: `pre-commit/check.js` gained `--verdict`, `--version-check` (warns when code changed, a version file exists and none is in the change set) and a `stray` check (editor, OS, merge and log leftovers such as `.DS_Store`, `*.orig`, `*.log`). The command file is a short relay; the gate's own checks are unchanged. 3 new tests.
- `/figma` maps the extracted colors and type sizes to the project's own tokens: `figma.js` reads a CSS token file (`--tokens <file>`, else the common names such as `src/styles/tokens.css`) and adds a Token column (exact match, `~` for the nearest within a small distance, `-` for none) and a token beside each type size. No token file means the tables are unchanged.
- `/kit` is a script: `skill-scope/kit.js` scores the situation against keyword lists for each row of the command table and prints the single best command, or the table when nothing matches. The table lives in the script, which a test checks against the command files, so the cheat sheet cannot name a command that does not exist. `/kit` now needs `skill-scope` installed, like `/next`.
- `/wrap-up` is split into script facts and Claude judgment: the new `handover/draft.js` prints the `Updated:` line, the commits since the last handover date, the uncommitted files, the existing next task and the size check, and with `--journal` the newest session-journal facts (asks, files edited, failed commands; read only, and it says so and falls back to git facts when there is no journal). The command now asks Claude to write only Current state, Last session, Decisions, Known issues, Next steps and gotchas. The draft never edits the handover. 5 new tests; the A/B on real finished sessions is not done yet, so the token saving is expected, not measured.
- Opt-in add-on `figma-code` and command `/figma-code`: `figma-code.cli.js` turns an exported Figma SVG into pixel-matched HTML and CSS with no model in the loop, in gated steps. `build` writes real HTML text (positioned by the font's rounded ascent and descent), boxes and circles as divs, nesting by containment only where it cannot change paint order, a flex row or column only where neighbouring boxes share a top or left edge and one equal gap, and inline SVG (reported) for gradients, paths, strokes, filters, masks, images and odd transforms; it then renders the SVG and the page in headless Chrome or Edge and diffs them with its own PNG reader (zero dependencies), reporting the percent of differing pixels and the worst regions, and missing fonts first. `standards` applies a declarative rule file (`standards.json`, every rule tagged safe or risky): safe rules as one batch, each risky rule alone with a re-render, reverted when the diff moves. `adapt` writes a Next (JSX plus CSS Module), Astro or Laravel Blade component, renders it back and diffs it, and never overwrites without `--force`. Measured on a synthetic Figma-style frame (header, three cards, gradient button, path): 0 of 153,600 pixels differ for the page and for all three adapted components; the risky `px-to-rem` rule at two decimals moved the diff to 0.18% and was reverted (now four decimals). Not yet run on a real export, an outlined-text export or a non-Arial font; the real-file pass needs your SVG and PNG. Pixel match holds only at the exported width and with the same fonts installed. Standards run on the build folder before `adapt`, so component class names are already renamed (the plan had them in the other order).
- `security-audit/recon.js` scans the files git tracks or does not ignore when the folder is a git work tree, so a gitignored sandbox, virtual environment or cache is never read; outside git it walks with a longer skip list (`venv`, `.venv`, `__pycache__`, `site-packages`, `target`, and more) and a 20,000-file cap that it reports. On this repo (a 31,500-file, 527 MB `_sandbox`) a scan went from over 90 s, past the `skill-hint` 30 s limit, to 0.6 s. The report now says which scope it used. 1 new test.
- Commands `/perf`, `/e2e` and `/recon` run the new perf-audit, e2e-scaffold and security-audit scripts directly, so the user chooses the moment instead of waiting for the model to load the skill (skill loading is model-judged; the October audit found it unreliable). The handover size hook at session start now also runs the memory-bank index check when that skill is installed and the project has a bank, silent when clean.
- Seven skills gained a companion script for their mechanical steps, so the model reads one summary instead of running greps and listings by hand: `perf-audit/weigh.js` (static payload weigh-in: JS/CSS gzip totals, heavy chunks and images, PNG without a modern sibling, fonts and `font-display`, blocking scripts, lazy and LCP attributes, unhashed names), `e2e-scaffold/init.js` (stack detect, write the Playwright config, fixtures and smoke test from the templates, wire `package.json` and `.gitignore`, refuse to re-scaffold), `astro-page/conventions.js` (`scan` the prefixes, folders, entry-script pattern and `client:*` use; `check` new files against them), `security-audit/recon.js` (routes, auth markers, data stores, env reads, outbound calls, sinks, masked secrets, obvious things, with `file:line`; an inventory, never a finding), `memory-bank/index.js` (`check`, `rebuild` and `init` for `INDEX.md`), `shopify-toolkit-install/get.js` (scratch clone, copy chosen skills, snapshot note, telemetry notice; never applies the opt-out) and `skill-ablation/archive.js` (archive and restore with a manifest, including the hooks block of `.claude/settings.json`). Each skill now calls its script and lists what still needs the model. `interpretation-checkpoint` got none: its only mechanical step is a glob, and its companion name would exceed the 30-character file-name rule. Token saving is expected, not yet measured; see the perf-audit gate note in the kit's memory.

### Added
- Mod `session-journal`: after every turn a script appends one line (the ask, files edited, commands run with secrets scrubbed, failures) to `~/.ai-dev-kit/sessions/<project>/<first-launch>.jsonl`, outside the project and separate from `handover.md`. ### Added

Opt-in; loads on its own for simulator, cutaway and exploded-view requests. Film output and sound are not included yet.

Rules are one line each, with numeric limits, and `(auto)` marks the ones a script can check. New `UI standard` row in the Active Standards table (`--active-standards ... ui`); company auto-detect drops it together with the design standard when a company brings its own design system.

### Added (project signature)
- Project signature, a core installer setting: the user chooses an alias at install (`install --signature <alias>`, an interactive prompt, or none), the kit never picks one. One stored alias goes in exactly three places: `abc-` classes and ids, `data-abc-` data attributes (RULE 11), `Abc` shared components. It fills the project table's "Selector signature" row (restored by `signature remove` and `uninstall --all`), and joins the Company Standards block and index when those are used. New command `signature set|remove|show` with `--dry-run`.
- `code-audit` rule `css-11` (review level, only when a signature is set) flags a class, id or data attribute the project defines without the alias. Custom code only: `node_modules`, `vendor`, third-party, minified and generated files are skipped, the names that package.json dependencies bring (Bootstrap, Bulma, Swiper, Font Awesome and others) are exempt, and `signatureIgnore` and `signatureExempt` in `.claude/code-audit.json` add more. The rule text tells the AI never to rename or prefix package, framework or library names.
- WCAG 2.2: `accessibility-standards.md` now targets WCAG 2.2 AA with RULE A11Y-19 to 24 (focus not obscured, drag alternatives, 24 px targets, consistent help, no redundant entry, authentication without a cognitive test).
- `ui-standards/theming.md` (dark mode and theme toggle, 11 rules) and `ui-standards/landing.md` (10 rules); `fields.md` gained select, async, multi-select, date-range, counter and tri-state rules.

### Added (open items from the company-standards comparison)
- `coding-standards/index.md` has a Precedence list (about 90 tokens): accessibility and security first and never waivable, then company standards, a design source for the look only, framework overrides, ui-standards and the file-type standards, and AI defaults never.
- New mod `gap-log` (observer, adds no model-visible text): every `STANDARDS GAP: <what is not covered>` line in an answer is appended to `.claude/standards-gaps.jsonl`. `RULE AI-12` now uses that exact phrase.

- Colour contrast (A11Y-09) as a code check: `contrastPairs` in `.claude/code-audit.json` (pairs of colour tokens with a minimum, or `"auto"` for text tokens against surface and background tokens). It follows `var()` chains and checks light and dark mode. Hex, `rgb()`, `hsl()` and `oklch()` are understood; alpha, `color-mix()` and `light-dark()` are reported as not checked (`a11y-09-skip`). A failing pair is `a11y-09`, a hard per-edit rule that cannot be waived.

### Added (signature enforcement, round 2)
- Component detection reads export lists, aliases (`export { X as Y }` checks the public name), `export default X`, wrapped exports (`export default connect(a)(X)`), `module.exports`, arrow components and classes. A Pascal-case function in a component folder counts as a component (the kit's naming rule makes functions camelCase).
- The signature check learns from installed packages: class names defined in the CSS of every dependency in node_modules (capped at 60 packages and 2 MB, cached until package.json changes) are exempt, not only the ones in a built-in table. `code-audit --suggest-exempt` groups flagged names by first word and prints the `signatureExempt` line to paste for libraries that are not installed (CDN).
- The interactive installer is testable: `AI_DEV_KIT_INTERACTIVE=1` forces the prompts on piped input (answers one per line; a closed input means Enter). Walking it showed and fixed three things: a second "install the default standards?" question after the company question already answered it, unreadable piped transcripts, and a bad alias that failed after files were written (it is now re-asked, and `--signature` is validated before anything is written).

### Added (signature enforcement)
- `signatureMode: "strict"` in `.claude/code-audit.json` turns the signature checks into hard rules (per edit, and a commit block on added lines only). Default stays review level.
- Shared component names are checked (`css-11-component`): exported components, `.vue`/`.svelte` files and Dart widgets in components, ui or shared folders should start with the capitalised alias. Pages, views, screens, tests and stories are skipped; `signatureComponentDirs` changes where to look.
- `bannedImports` (rule `ban-01`, hard): a project or company lists libraries it forbids (names, sub-paths, globs, optional message) and an import of one fails the edit check and blocks a strict commit. Nothing is banned by default.
- `projectConfig` in the audit engine: one merged config (code-audit.json, the install manifest, package.json) used by the audit, `edit-check` and the commit check.

### Added (enforcement)
- `code-audit`: `--changed` (only lines changed since HEAD); a `DEVIATION: <rule id> <reason>` comment that waives a rule on its line and the next, counted in the report, with accessibility and security rules unwaivable and a reasonless, unknown or stale waiver reported; 10 `ui-*` rules that check the UI standards a script can verify (`standard` filter `ui`, `dev`), on only where `ui-standards.md` is installed.
- Strict mode (`.claude/edit-check.json`): `"strict": true` makes the `edit-check` hook report findings as hard rules and makes the pre-commit check block a commit that adds one on a changed line; `"scope": "changed"` limits the per-edit check to changed lines. Off by default.
- UI rule tags are now `(check: <rule id>)` where a script checks the rule and `(browser)` where only a browser test can; the old `(auto)` tag is gone.

### Changed
- The `standards-chain` mod now reads `ui-standards.md` plus at most two partials chosen by keywords in the file path (`button.css`, `DataTable.tsx`, `login.html`), only for UI-like files and only when the files are installed; `{"ui":false}` in `.claude/standards-chain.json` turns it off. It also covers `.vue` and `.svelte`.
- The `standards-chain` mod requires `company/INDEX.md` to be read before code and UI edits when it exists, covers more UI file types (`.php`, `.vue`, `.svelte`, `.dart` and others) for company standards only, and no longer demands a default standards file that is not on disk.
- `uninstall --remove-standards` keeps `coding-standards/company/`.

### Added
- Installer now owns slash commands. `install` copies them (Claude Code and OpenCode), records each with a hash in the manifest, `update` refreshes unedited ones and adds newly eligible ones, and `uninstall` removes unedited tracked ones; edited or foreign files are never touched, `--no-commands` skips it. Before this the assistant copied templates by hand, so nothing refreshed or removed them. `skill-scope/auto.js run <skill> <script>` restores an archived skill before running its script; the six commands for archivable skills (`/audit`, `/stale`, `/version-bump`, `/resolve-conflicts`, `/responsive-check`, `/optimize-assets`) use it, because with archiving on by default their direct script path would not exist yet.
- Installer lifecycle for hooks: `update` now adds hook blocks that a newer kit ships (only where the project already holds a kit hook), and `uninstall --remove-hooks` removes only the entries identical to the kit's, leaving every other hook and setting. Before this, an updated project never received the new archiving and size hooks, and an uninstalled one kept dangling ones.
- `handover/size.js check`: counts handover lines, session sections and `learnings.md` bullets and prints a line only when a limit is crossed. Run by a new session-start `hook:core` block and by `/wrap-up`, which fixes what it names in the same rewrite. Until now the 120-line ceiling was a rule the model had to remember; this project's own handover reached 121 lines with six stacked sessions.
- `ux-theory` skill: colour, type, composition (layout, hierarchy, proximity, alignment, balance, white space), motion (transitions, easing, micro-interactions) and fx (sfx, vfx) in field terms, one topic file each, read on demand. Archivable: it matters while a theme is built or extended, not after. Existing tokens always win over it.
- Automatic skill archiving. `skill-scope.auto.js` archives every per-session-archivable skill and restores one when the stated task names its trigger word (`skill-scope.triggers.json`, single source). Two `hook:core` hooks in `hooks-enforcement` run it at session start (archive all) and per prompt (restore only, silent unless it restored something); `/next <task>` is the explicit version and works in any tool. Archive and manifest code moved into the shared `skill-scope.move` companion so a project without `install-kit` still has it. Replaces the passive "only if the user volunteers the next task" rule in `handover`.

### Fixed
- `skill-scope.auto` crashed when installed: the installer strips the skill prefix from companions (`auto.js`, `move.js`, `triggers.json`), so the `skill-scope.`-prefixed `require` and paths in `/next` and the hooks pointed at files that do not exist. Found by a scratch `install-kit` install. The engine now loads whichever name exists, and the hook line names the restored skill's `SKILL.md` so the model reads it in the same turn (a restored skill is not in the session's skill list until the next session; checked with headless `claude -p`).
