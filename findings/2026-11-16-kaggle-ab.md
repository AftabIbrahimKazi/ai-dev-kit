# Kaggle executor A/B vs Claude writing the plan (2026-11-16)

Three small plans (P1 CSV parser + tests, P2 Stack/Queue + tests, P3 formatBytes + tests + HTML page), 2-3 tasks each, module style stated in every task. Arm C: Claude (Haiku, `claude -p`) writes everything and runs the checks. Arm G: `/kaggle run` on the GPU, staged files copied in, Claude (Haiku) called only if a Check failed. Plan authoring cost is the same in both arms and is not counted. Success = all Target files exist and every `node --test` file passes (HTML ends with `</html>`).

| Plan | Arm C cost | Arm G Claude cost | Arm G first pass |
|---|---|---|---|
| P1 | $0.0141 | $0.0086 (one test file fixed) | fail, fixed |
| P2 | $0.0100 | $0.0000 | pass |
| P3 | $0.0084 | $0.0000 | pass |
| Total | $0.0326 | $0.0086 | 2 of 3 |

All six runs end passing. Claude spend on the GPU arm is 74% lower (n=3, one run per cell, Haiku as the Claude arm).

Caveats: the numbers are tiny because the plans are small and Haiku is cheap; the saving scales with plan size only if first-pass quality holds, which these plans cannot show. A dearer Claude model would widen the gap. GPU arm costs about 7 minutes of wall time and about 7 GPU minutes per plan (30 h a week free), against Claude's under a minute. The failure was cross-file consistency again (P1 test file), caught by the real Check, not by the local gates. Ship as opt-in; the saving is real on this sample, not yet proven on large plans.
