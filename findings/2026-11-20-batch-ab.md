# batch mod: A/B evidence (2026-11-20)

Ship-gate evidence for `mods/batch` (see `mod-writer`: correctness, then tokens, then speed).

## Method
- Headless runs: `claude -p ... --output-format json --no-session-persistence`, same prompt in every arm, project read-only (`--allowedTools Read,Glob,Grep[,mcp__batch__run]`). Tokens are `input + cache write + cache read + output` from the JSON usage block.
- Arms: no mod; v0.2 (reducers `only`, `maxLines`, `count`, `header`); v0.3/v0.4 (adds `Map`, `symbols`, `headings`, empty-match fallback, ledger). 2 runs per cell.
- Tasks: T1 report line count and purpose of 12 named files; T2 discover and describe every `.js` in two folders; T3 report the frontmatter description and `##` headings of 6 `SKILL.md` files.
- Scoring by script against the files: line counts, file lists, heading recall (headings inside code fences excluded), plus a keyword check for hedged answers. The first scoring pass had two scorer bugs (basename collision, fenced headings), fixed for all arms and all runs rescored.

## Ledger (v0.4 runs, Sonnet)
All 6 sessions used the tool: 9 calls, 70 ops, 452k characters read, 38k returned (92% kept out of context; two small sessions were net -2% from labels). Whole-session tokens fall about a third, not 92%, because the system prompt and cached context dominate.

## Limits
- n=2 per cell. Totals swing widely inside one arm (Haiku v0.2 T2: 293k and 515k).
- One repo, three read-only tasks, no editing task, Haiku and Sonnet only.
- v0.4 against v0.2 is within noise on Sonnet (-8%); the new reducers show on T2 and T3, not T1.
- Wall time was not worse in the mod arms (Sonnet T3 9 s against 36 s; Haiku T2 18 s against 22 s).
- All arms ran with the user's other global mods (including `prefilter-rank`) active.
- Nested calls inside the tool do not return other mods' notes, so `prefilter-rank`'s ranking is lost for a Grep run inside a batch call (probe: `$.tool.call` returns only `result` and `text`). Rank with a plain Grep/Glob first.
