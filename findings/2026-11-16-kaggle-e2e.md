# Kaggle executor, live end-to-end (2026-11-16)

Plan: 3 small tasks (slugify.js, its node:test file, a config.json + config.js pair). Real `kaggle` CLI, real GPU, `kaggle.cli.js run plan.md`.

- Wall time 6 min 54 s for the whole run (push, GPU session about 7 min, fetch, stage, gate). Ledger and `usage` matched.
- Plan lint caught a real flaw before any GPU time: task 2 listed a Context file that task 1 creates. Tasks must stand alone; the plan was fixed.
- Result 2 of 3 passed the first time. Task 3 came back with `FILE:` lines but no code fences; the parser was strict. Fixed: an unfenced body now runs up to the next `FILE:` line (test added). Re-parsed, both files pass the gates.
- Cross-file consistency is the weak point: the test file used ESM `import { slugify }` against a CommonJS module (the task text only said "exports a function"), so `node --test` fails. The local gates cannot see that. Mitigation: plan rule to state module style and export form; `Check:` commands run in the repo after review (Claude's job).
- Not done: the A/B against Claude executing the same plan (tokens saved vs fix cost). One small plan cannot decide it; needs 3+ plans per arm like the kit's other gates. Until then the add-on ships as opt-in with measured speed and a known weakness, not as a proven saving.
